# 분산 서비스 간 정합성

## 핵심 정리

- A → B 의 RestClient 호출 시 B 장애를 방지하기 위해 retry
- 어디까지가 성공의 정의인가? — Redis 적재 시점이라면 at-least-once 가능
- Redis 적재 실패 또는 B 서버 응답 없음 → retry 후 503 처리
- B → C 는 쿠폰 발급 이벤트를 Kafka 로 전달
- 스케줄러로 Redis 에 적재된 데이터를 탐색하여 상태 감지 → C 서버의 RDB 데이터를 확인. 성공이면 성공 데이터로 업데이트, 없으면 다시 재발행
- 쿠폰 발급 후 B 의 상태 업데이트를 위해 C → B 로의 Outbox 저장
